# Noted

Noted is Oxy's local-first notes and meeting-capture product for iOS, Android
and the web.

```text
Expo client -> per-account SQLite -> Nilo API (api.nilo.so)
            -> on-device speech and language models

In-app Alia chat -> Alia agent runtime
Future hosted point inference -> Oxy -> Kaana
Future agent/chat/tools/memory -> Alia -> Oxy -> Kaana
```

Noted has no server of its own: its notes live in Nilo, and the old Noted API
(`api.noted.oxy.so`) is retired. There is no secondary store or remote fallback.
The client writes locally first and synchronises afterwards, so reading remains
available offline and survives an interrupted edit.

## Local storage and browser tabs

Multiple browser tabs must remain usable at the same time: each can read and
edit notes, and committed local changes refresh the other tabs for that account.
Opening another tab must not require closing the first or clearing browser data.

SQLite remains the read source of truth. TanStack Query manages mutation state
and remote resources; it does not replace SQLite or coordinate its file handles.
On web, tabs share access to one SQLite owner through an origin-wide broker.
The owner serializes each account-bound operation, including whole transactions,
and broadcasts account-scoped invalidations. Each tab keeps its own active
account, while each account keeps its own database and unsynchronized writes.

Losing a tab must preserve persisted notes. Ownership can transfer only after
the browser releases the previous owner's storage lease. An unacknowledged write
may already have committed, so ownership changes must not automatically replay
it. Storage recovery never deletes the OPFS pool or substitutes a remote or
in-memory notes store.

## AI ownership

Current recording intelligence is local to the user's device:

- native speech-to-text uses whisper.cpp;
- the browser uses an ONNX Whisper build;
- transcript enhancement uses a downloaded language model on the device;
- audio and transcript content do not leave the device for those operations.

The in-app Alia chat sheet (`components/alia-chat.tsx`) talks to Alia, the
agent runtime, with the signed-in user's Oxy session; the notes' capability
catalog it can use is registered by Nilo. Noted itself sends no prompt to a
provider and has no inference route. If Noted later adds hosted one-shot inference, the product must
call Oxy and Oxy must route it to Kaana. If it adds an agent, chat, tool or
memory capability, the product must call Alia, which calls Oxy, which calls
Kaana.

Kaana is the sole hosted inference data plane. Its only canonical signed origin
is `https://kaana.ai`, never a hostname under `oxy.so`. Provider keys live only
encrypted in Kaana PostgreSQL/KMS and must never be placed in Noted source,
PostgreSQL tables, GitHub secrets or environment variables. Noted's Oxy service
credential is an application identity, not a provider key. Any future
application, bot or agent binding must use its byte-exact opaque primary key;
display-name, sorted-list and first-result fallbacks are forbidden.

## Note and artifact contract

Noted's server is Nilo (`api.nilo.so`): a note is a row of the user's
personal-workspace `notes` database, served by Nilo's `/notes`; the shapes are
`@oxy.so/nilo-contracts` `notes.ts`. A recorded note has two parts:

- its content, Nilo blocks (flat: `parentBlockId`, `order`, `content`), edited
  with Bloom's block editor — the user's blocks and the recorder's, the latter
  known by id (`lib/notes/blocks.ts` `GeneratedMap`), so a rebuild replaces
  exactly its own and never what the user wrote;
- an artifact containing transcript provenance, speaker/timing references,
  transcript revision and user overrides, kept with the recorder's map in the
  note's app data on Nilo (`appData`, written on its `revision`).

Artifact types live in `@noted/shared-types`. `CAPTURE_PROFILES` and
`DOCUMENT_INTENTS` are the source tuples from which the unions derive.

Three invariants are load-bearing:

1. Only a `final` artifact synchronises; a changing `live` artifact remains on
   the device.
2. Artifact writes compare-and-swap on `transcriptRevision` in SQL locally, and
   the app data as a whole on its revision on Nilo (a stale write is `409
   STALE_APP_DATA`; the client takes the server's and sends again).
3. Missing `artifacts` or `itemOverrides` means “leave existing state alone”. An
   explicit empty array means “clear it”.

## Note sync contract

- **Edits carry their base.** `PATCH /notes/:id` sends `baseUpdatedAt`, the
  server `updatedAt` the edit sits on; a stale base is `409 STALE_NOTE` with the
  current note and nothing is written. The client keeps the other version as a
  conflict copy (with fresh block ids: a block belongs to one page) and retries
  once. A create (`POST /notes` with the device's id) answers 200 when the note
  already exists, and the client then writes its version on top.
- **Content is merged by block, not by text.** The editor sends what it changed
  against the blocks it started from, and the store merges that onto the note
  as stored (`mergeBlocks`); nothing writes a whole note over a recording that
  moved on.
- **Pulls are passes.** `GET /notes/sync?cursor=&limit=` returns `notes`,
  `deleted`, `cursor`, `hasMore`, and at a pass's end the labels and folders.
  A `full` pass is the whole set: every note it returns is marked with the pass
  (`notes.sync_pass`), and at its end what it did not see and the device has not
  changed is gone. `reset` means the workspace was reset since: everything on
  the device goes first, unsent edits included. Each page commits its rows and
  cursor in one transaction.

## Folders

A note is filed in at most one folder (`notes.folderId`). Folders nest up to three
levels (`folders.parentId`, rules in `lib/folder-tree.ts`: no cycles, no deeper
than three, the whole subtree counts when moving a branch), and a name is unique
within its parent. Deleting a folder moves its notes and subfolders up to its
parent instead of unfiling them. `GET/POST /folders`, `PATCH/DELETE /folders/:id` mirror
labels; deleting a folder unfiles its notes in the same transaction and moves
each note's `updatedAt`, so other devices pull the change. A note write naming a
folder the caller does not own is refused with `400`. On the wire `folderId` is
optional with the same rule as the generated half: absent means "no change",
`null` means "take it out of its folder". `GET /notes?folder=<id>` filters.

On the device, `folders` is a copy of the server's list (read offline, written
online, like labels) and `notes.folder_id` is local. A pull brings folders in
before notes. A note with unsent edits that names a folder no longer in the list
is unfiled locally, because the server would refuse it as `Unknown folder` on
every retry; a clean note naming a folder not yet pulled is left alone, since the
server's version is the right one.

## Version history

A note's history is its Nilo page's (`/pages/:id/versions`): the blocks as they
were before the first change after a quiet spell, and before every restore. The
editor's toolbar opens it; restoring applies the version's blocks as an
ordinary local edit (set whole, so the recorder's map is cleared and restored
text is the user's), and it syncs like any other.

## Attachments and Oxy file references

A note's attachments are Oxy files the owner already has (picked from their Oxy
file manager; Noted uploads nothing). The note keeps their ids
(`attachments`), and Nilo keeps them as the files property of the note's page.

**Who uses the file is Nilo** (Oxy ADR 0043 D4): Nilo stores the page, serves
its files and is the only server that sees a file leave the page or the page
go. Noted has no server that writes notes (its old one is retired), so it
registers no reference of its own, holds no `files:references:write` and
receives no file events. The one reference an attachment needs:

| Application | `entityType` | `entityId` | Created by |
|---|---|---|---|
| Nilo (`NILO_OXY_APPLICATION_ID`) | `page` (`NILO_FILE_ENTITY_TYPE`) | the note id (= the Nilo page id) | the file's owner, from Noted |

**Noted's half is the owner's link.** An attachment is usually a private file,
and Oxy lets an application reference (and serve) a person's private file only
after that person attached it to the application with their own session (ADR
0041 D4, ADR 0021); Nilo's service token cannot do it for them. So every sync
ends with `syncAttachmentLinks` (`lib/files/attachment-links.ts`):

- `attachment_links` (local, one row per note and file) is derived from
  `notes.attachments_json` on every pass: a new attachment is `pending`, one
  that left its note or whose note was deleted for good is forgotten. A device
  that already had attachments back-fills on its first pass.
- **The owner links before the note names the file on Nilo**: the outbox
  links a note's due attachments (`linkNoteAttachments`) before it sends the
  note. Once the page names a public file, Nilo's reconciliation may reference
  it with its own token first, and Oxy then answers the owner's later link
  `exists` without recording the owner, so the ADR 0021 grant never lands
  (Oxy's to fix: the insert ignores the conflict). A link needs no page, and
  one for a page never saved is removed by Nilo's reconciliation. A failed
  link never holds the note back; the end of the sync retries it, along with
  the back-fill, notes pulled from elsewhere and the weekly re-checks.
- The file is read first (`GET /assets/:id`, the owner's session). `active`
  and not yet referenced: linked (`POST /assets/:id/links`, the target above),
  then `linked`, re-checked weekly and linked again unless the owner's own
  reference is there (one Nilo made with its token carries no grant).
  In the owner's trash or blocked: `unavailable`, never linked (a new
  reference takes a file out of the trash, undoing the owner's decision),
  checked again with backoff up to a day. Deleted: `missing`. Another
  account's file: `not_owner` (only its owner can attach it). Both are final.
  Failed requests back off from a minute to a day; nothing gives up for good.
- **Noted never unlinks.** A file can be on the page twice (an attachment and a
  file block share one reference), and only Nilo knows when the page stops
  using it. The rest is Nilo's, with its service token (OxyHQ/Nilo#89): its
  `page` reconciliation inventories `page_files` and every file id in a live
  page's properties (trashed pages included), so these owner links survive it;
  it removes the reference when a file leaves the properties or the page is
  deleted for good (emptied trash, a hard delete, `POST /notes/erase`, a
  reset); and it receives the file events.

**What the editor shows.** The server decides: a note's `removedAttachments`
(Nilo's, from the file events it receives) are the attachments Oxy no longer
serves, kept in `notes.removed_attachments_json`, which only a server note
writes, and shown as removed in the editor and with no thumbnail on the card.
The owner's own `GET /assets/:id`, which the editor makes anyway for the name,
type and size, only adds what Nilo cannot know: why ("This file is in your
trash" rather than "This file is no longer available"), and the state of a
file Nilo holds no reference to (its link still pending, or another account's
file), about which it is told nothing. The note keeps the attachment until it
is removed, so a file restored from the trash comes back.

Requires the Oxy API with ADR 0043 stage 1: an earlier API inferred visibility
on a link and made a public file linked to a `page` private.

## Account data

`GET /notes/export` (Nilo) returns every note (trash included), label and
folder Noted keeps as one JSON file. `POST /notes/erase` with
`{"confirm":"DELETE"}` erases every note, folder and label for good in one
transaction, leaving tombstones so other devices drop them; the rest of the
user's Nilo workspace stays, and the Oxy account itself is Oxy's to delete.

Settings → Account → "Erase my Noted data" calls it, then clears this device
(`lib/db/erase-local.ts`): recordings' audio first, then every account table
including the outbox — left behind, pending uploads would re-create the erased
notes. Device preferences and downloaded models stay. The server goes first so a
failed request changes nothing.

## Identity and sharing boundary

Every note is a private page of the signed-in user's personal Nilo workspace,
which takes no members; Nilo scopes each request to the verified Oxy user. No
note has a visibility, audience, collaborator or public-share-link field in
Noted.

That is why Noted deliberately has no CrowdSource integration today: there is
no public subject for another user to report. The feedback endpoint is a private
support inbox and must not expose a report or device metadata to a community
jury. If Noted gains a published note, public link or collaborator, this
decision must be revisited before that surface ships.
